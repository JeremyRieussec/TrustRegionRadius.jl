\begin{abstract}
We audit \texttt{Article3/fig-architecture.tex} and
\texttt{Article3/old\_versions/TRR-algorithmes.tex} against the package source.
Thirty-five claims were checked. Twenty-six are discrepancies, of which fourteen
are wrong rather than merely out of date or incomplete. Three of the fourteen
would mislead a reader about what the code does:
the algorithm accepts a step on $\eta_1$ where the package accepts on $\eta$, the
$\Rgrad$ pseudo-code has two branches where the code has four and uses the old
$\gamma$ numbering, and the $\Rrtr$ pseudo-code omits the acceptance branch that
the code calls mandatory. Both documents have been corrected and both compile.
\end{abstract}

\section{The three errors that matter}\label{sec: three}
% =============================================================================

These are wrong rather than out of date, and each would lead a reader to a
different algorithm from the one implemented.

\subsection{Acceptance was attributed to the wrong threshold}

The algorithm read
\begin{verbatim}
    \If{$\rho \ge \eta_1$}{      % acceptance
\end{verbatim}
and declared its inputs as $0 \le \eta_1 < \eta_2 < 1$, so $\eta$ did not appear
at all. The package has three thresholds and accepts on the first of them.
\texttt{src/Trust-region/common.jl:562} reads
\begin{quote}\ttfamily\small
st.accepted = st.$\rho$ >= p.$\eta$\qquad\# acceptance is decided by
$\eta$ alone
\end{quote}
and \texttt{common.jl:161} enforces $0 \le \eta \le \eta_1 \le \eta_2 < 1$.

This is not a notational difference. With $\eta < \eta_1$ the band
$\rho_k \in [\eta, \eta_1)$ opens, in which the step is accepted and the radius
nonetheless contracts. A document that accepts on $\eta_1$ cannot express that
band, and the band is the subject of an entire experiment,
\texttt{exp14\_acceptance\_band.jl}. The default $\eta = \eta_1$ reproduces the
coupled behaviour, so the old text describes the default rather than the rule.

\subsection{\texorpdfstring{$\Rgrad$}{R-grad} had two branches and the old
\texorpdfstring{$\gamma$}{gamma} numbering}

The pseudo-code read
\begin{verbatim}
    if rho >= eta2 and |s| > Delta/2 :  mu <- gamma2 * mu
    elseif rho < eta1 :                 mu <- gamma1 * mu
    return mu * |g_{k+1}|
\end{verbatim}
The code at \texttt{src/Radius\_updates/rules.jl:516--529} has four branches, and
expansion uses $\gamma_3$:
\begin{verbatim}
    if     rho <  eta1                    : mu <- gamma1 * mu   (contract)
    elseif rho <  eta2                    : mu <- gamma2 * mu   (shrink)
    elseif !half_test || |s| > Delta/2    : mu <- gamma3 * mu   (expand)
    else                                  : mu unchanged        (hold)
\end{verbatim}
The missing middle branch is a mild contraction on a merely successful step, and
the old text sends that case to the \emph{expansion} branch by omission. The
$\gamma_2$ for expansion is the numbering before the rule was renumbered;
\texttt{benchmark/config.jl} records the change and warns that a positional call
can pass silently under the wrong reading.

\subsection{\texorpdfstring{$\Rrtr$}{R-RTR} omitted the branch the code calls
mandatory}

The pseudo-code branched on $\widetilde\rho$ alone. The code at
\texttt{rules.jl:993--1010} branches on the acceptance flag first, and its
docstring says why:

\begin{quote}\small
Branching on \texttt{accepted} is mandatory, not defensive. Comparing a
\emph{classical} $\rho$ against the \emph{retrospective} thresholds would leave
the radius untouched for $\rho \in [\widetilde\eta_1, \eta)$, an unsuccessful
iteration with no contraction, which forfeits weak admissibility and, since a
rejected step changes neither the model nor the iterate, reproduces the same
subproblem for ever.
\end{quote}

The old pseudo-code also used $\gamma_2$ where the code uses $\gamma_3$, and
$\gamma_1$ where the code uses $\gamma_2$, and invented a $\gamma_0$ that does
not exist. The correct rule is
\[
  \Delta_{k+1} =
  \begin{cases}
    \gamma_2\norm{s_k}                       & \text{rejected, } \rho \ge 0,\\
    \min\{\gamma_2\norm{s_k}, \gamma_1\Delta_k\} & \text{rejected, } \rho < 0,\\
    \max\{\gamma_3\norm{s_k}, \Delta_k\}     & \text{accepted, } \widetilde\rho \ge \widetilde\eta_2,\\
    \Delta_k                                 & \text{accepted, } \widetilde\eta_1 \le \widetilde\rho < \widetilde\eta_2,\\
    \gamma_2\norm{s_k}                       & \text{accepted, } 0 \le \widetilde\rho < \widetilde\eta_1,\\
    \min\{\gamma_2\norm{s_k}, \gamma_1\Delta_k\} & \text{accepted, } \widetilde\rho < 0.
  \end{cases}
\]

\subsection{\texttt{fig-architecture.tex}}

Six edits. The radius-rule box now reads ``eleven mechanisms, the six
criticality-anchored ones with a variant $\omega_k = \tau_k$''. The subproblem
box gains Krylov CG-Lanczos and names \texttt{EigenPoint} as a wrapper. Step~1
becomes ``Build $m_k$, $\omega_k$'' and Step~3 ``$\rho_k$, accept if
$\rho_k \ge \eta$''. The loop label becomes ``one iteration, shared by the three
problem classes''. The record gains $f_k$, accepted, $\gamma_k$, $\xi_k$ and
$\tau_k$; the diagnostics box gains $\theta_k$. The caption gains one sentence
saying that Step~1 evaluates the measure and that Step~3 accepts on $\eta$ while
Step~4 scales on $\eta_1$ and $\eta_2$.

This file is \verb|\input| by \texttt{Survey-part3-v1.tex} at line 599, so the
change reaches the paper.

Twenty-three edits, each asserted to match once. The three of
Section~\ref{sec: three}, the counts, the axes table, the model table, the
experiment table extended from seven rows to sixteen, the success criterion, and
a new paragraph (b$'$) explaining that acceptance and scaling are two decisions.
The note compiles to ten pages with no errors.

\section{What was not changed, and why}\label{sec: notchanged}
% =============================================================================

\paragraph{The location of the algorithms note.}
\texttt{TRR-algorithmes.tex} sits in \texttt{Article3/old\_versions/}. We
corrected it in place because that is what was asked, but a note describing the
current package does not belong in a directory named for superseded drafts. The
directory holds four other superseded drafts of the numerical study. Moving it
is a decision about the repository and not about the mathematics, so we leave it.

\paragraph{The note is in French and the study is in English.}
We kept the language. Changing it is an editorial decision.

\paragraph{The five families.}
The section heading ``Les cinq familles'' still shows five representative rules
out of eleven. That is a reasonable exposition and not an error, so it stands.
The axes table now gives the full list, so the count is available.

\paragraph{The bibliography.}
\texttt{TRR-algorithmes.tex} points at \verb|\bibliography{../References}| and
compiles without it, so the citation keys were not checked against
\texttt{References.bib}. That is a separate audit.

\section{Discussion}\label{sec: discussion}
% =============================================================================

\paragraph{The errors cluster where the package changed.}
Most of the wrong claims concern things the package gained after the note was
written: the third threshold $\eta$, the criticality measure $\omega_k$ in
place of $\norm{g_k}$, the \texttt{accepted} flag, the second-order stopping
test, and the rules and models added since. The Steihaug and Mor\'e--Sorensen
pseudo-code, which describes parts that have not moved, is correct line by line.
That is the expected pattern and it says where to look next time.

\paragraph{One error is of a different kind.}
The $\gamma$ numbering in $\Rgrad$ and $\Rrtr$ is wrong because the rules were
renumbered, and \texttt{benchmark/config.jl} carries a comment warning that a
positional call can pass silently under the wrong reading. The note is exactly
that kind of silent reader. A document that states $\gamma_2$ where the code
means $\gamma_3$ produces plausible radii rather than a visible failure, which is
the same hazard the comment describes.

\paragraph{The acceptance threshold is the one to fix first.}
Of the three errors of Section~\ref{sec: three}, the acceptance threshold is the
one that changes what a reader would implement. The other two are wrong about
branches within a rule; this one is wrong about the trust-region method itself,
and it removes the degree of freedom that \texttt{exp14\_acceptance\_band.jl}
exists to measure.
